NeuroAlpha

The first bot in this repo with no hand-written strategy. A convolutional network reads the whole map once per turn and gives every site we own a probability for each of its five moves. For now it learns by watching DexBot, the strongest bot here; reinforcement learning comes next.

The choice

Why a convolutional network, not a transformer

Transformers win when there is a lot of data and little structure to exploit. Halite I is the opposite: the rules have strong structure, and a good architecture builds it in rather than learning it.

Every move is local

A site chooses one of 5 moves, and merging, capture and overkill damage all happen within a step or two. A convolution is exactly "look at your neighbourhood, apply the same rule everywhere", so one small kernel serves 2,500 sites.

CNNBuilt in: the same weights at every site.TransformerHas to learn locality from data.

The map is a torus

Walk off the east edge and you arrive on the west edge. Every convolution here pads by wrapping around, so a site on the border sees exactly what it would see in the middle, with no artificial walls.

CNNOne line of index arithmetic.TransformerNeeds periodic position encodings.

Any map size, 20 to 50

A fully convolutional network has no fixed input size: the same weights run on a 20x20 duel and a 50x50 six-player map. Training batches group frames of the same size.

CNNSize-free by construction.TransformerAlso size-free, at a quadratic cost.

One second per turn, on a CPU

On 50x50, one 32-channel 3x3 layer costs about 23 million multiply-adds. Full attention over 2,500 sites costs 6 million pairs per layer before any channels. Our whole network runs in about 110 ms per turn in plain Rust.

CNNLinear in the number of sites.TransformerQuadratic in the number of sites.

What attention would add is long range: a rich region 20 sites away, or where the enemy front is. NeuroAlpha gets that more cheaply with dilated convolutions and a global summary added at every block (below).

The network

One forward pass, five numbers per site

Hover or tap a layer to see what it does.
h = relu(conv3x3(x) + b) stem: 11 planes to 32 channels
h = relu(h + conv3x3d(h) + b + meanmap(h) · G) x10 blocks, dilation d
logits = h · W + b 5 moves per site, keep our sites

Each block adds its convolution to its input (a residual connection, so ten blocks train as easily as two) and adds a summary of the whole map: the mean of every channel over the map, mixed by a 32x32 matrix G and broadcast to every site. That is how a site on the west coast knows the game is turning against us in the east.

Receptive field

How far can one site see?

A 3x3 convolution sees one step in every direction. Stack the network's eleven layers plainly and a site sees 11 steps: not enough on a 50x50 map. Dilation spreads a kernel's taps d sites apart, so the view grows with the sum of the dilations instead.

steps in each direction with dilation
with the same number of plain 3x3 layers

After all 11 layers a site reads a 55x55 window: more than the largest map. The pattern 1, 1, 2, 1, 2, 4, 1, 2, 4, 8 repeats small dilations between large ones, so nearby detail is never skipped. The global summary covers the whole map from the first block on.

Next

Phase two: beat the teacher

A cloned network is at best as good as DexBot, and small mistakes compound because it never saw the positions its own errors create. Reinforcement learning fixes both: starting from these weights, the network plays itself and a pool of opponents, and a value head learns who is winning. Then PPO moves the policy toward moves that led to better final ranks, not toward what DexBot would have done.
